# Decision Log — Snyk Security Scan (Config H)

## Preamble

This document is the rule-mandated **decision log** for the Snyk Security Scan (Config H) exercise executed against the `blitzy-cal` (Cal.com monorepo) codebase. The source of every decision recorded below is the Agent Action Plan (AAP) for Config H, which encodes the user's four CRITICAL directives — (1) install and authenticate the Snyk CLI via `SNYK_TOKEN`, (2) execute the Snyk SAST scan (`snyk code test`) and capture its SARIF output, (3) execute the Snyk SCA scan (`snyk test`) and capture its JSON output, and (4) normalize and merge the findings into a single-line minified JSON artifact named `findings-config-h.json` conforming to a 5-field-per-finding schema (`file`, `line`, `severity`, `cwe`, `description`). The artifact you are reading is required by the user-specified **Explainability rule** (AAP §0.7.1.1), which mandates that every non-trivial implementation decision be documented as a Markdown table of "what was decided, what alternatives existed, why this choice was made, and what risks it carries" and that every deviation from a literal or obvious interpretation of the requirements have an explicit entry. A **bidirectional traceability matrix is NOT applicable** to this exercise because this is not a migration or refactor — no source-construct-to-target-implementation mapping exists; per AAP §0.6.2 the decision-table form alone is the deliverable. This document is the **SINGLE SOURCE OF TRUTH** for every "why" decision across the Config H exercise: per the Explainability rule, rationale is NOT embedded in code comments in `findings-config-h.json`, `executive-presentation.html`, or `scripts/normalize-snyk-findings.mjs`; this log is the only place where rationale lives.

## Scope of Decisions Captured

This log enumerates decisions across five surfaces of the Config H exercise: (a) Snyk CLI installation, authentication, and invocation; (b) SAST scan (`snyk code test`) execution and SARIF parsing; (c) SCA scan (`snyk test`) execution and Snyk JSON parsing; (d) normalization, merging, severity mapping, prefix tagging, truncation, and serialization to `findings-config-h.json`; and (e) governance artifacts (this `decision-log.md` and the rule-mandated `executive-presentation.html`). Decisions internal to the executive presentation's visual identity, slide ordering, or CDN pinning are NOT duplicated here — those are dictated by the Executive Presentation rule (AAP §0.7.1.2) and are non-trivial only insofar as the rule itself constrains them; the rule text governs.
