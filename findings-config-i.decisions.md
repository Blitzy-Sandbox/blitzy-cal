## Failure Modes

This run completed all five directives successfully. No failure path was exercised. For posterity, the documented failure-mode posture is:

- **Toolchain unavailable** → Tier-1 deviation D1 documents the pre-installed binary.
- **Cold-start timeout (> 120 s)** → write fallback `findings-config-i.json` containing `[]\n`; capture `docker logs sonarqube-test`; trigger teardown; exit non-zero.
- **Scan EXECUTION FAILURE** → write fallback `findings-config-i.json` containing `[]\n`; preserve `/tmp/blitzy_scan.log`; trigger teardown; exit non-zero. (This path WAS exercised twice prior to D6/D7/D8 being applied; the diagnostics drove those decisions.)
- **API export error** → write fallback `findings-config-i.json` containing `[]\n`; trigger teardown; exit non-zero.
- **Unknown severity value** → raise exception; record in this log; trigger teardown; exit non-zero. (Not exercised.)
